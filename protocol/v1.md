# TapBoard WiFi Protocol v1

## Ports

| Role | Port | Transport |
|------|------|-----------|
| Discovery | `19528` | UDP broadcast / unicast reply |
| Session | `19529` | TCP |

## Discovery

**Client → LAN (broadcast):**

```
TAPBOARD_DISCOVER
```

**Companion → client (unicast):**

```json
{"v":1,"type":"discover_reply","name":"DESKTOP-ABC","host":"192.168.1.10","port":19529,"pinRequired":true}
```

## Session framing

TCP stream of length-prefixed JSON frames:

1. `uint32` big-endian payload length `N`
2. `N` bytes UTF-8 JSON object

Every message includes `"v": 1` and `"type": "<name>"`.

## Messages

### `hello` (client → server)

```json
{"v":1,"type":"hello","client":"TapBoard Android","clientVersion":"1.0.0"}
```

### `hello_ack` (server → client)

```json
{"v":1,"type":"hello_ack","server":"TapBoard Companion","serverVersion":"1.0.0","authRequired":true}
```

### `auth` (client → server)

```json
{"v":1,"type":"auth","pin":"123456"}
```

### `auth_ok` / `auth_fail`

```json
{"v":1,"type":"auth_ok"}
```

```json
{"v":1,"type":"auth_fail","reason":"invalid_pin"}
```

### `mouse` (client → server)

```json
{"v":1,"type":"mouse","dx":12,"dy":-4,"buttons":0,"wheel":0,"hwheel":0}
```

- `dx`, `dy`: relative movement in pixels (companion applies sensitivity)
- `buttons`: bit0=left, bit1=right, bit2=middle (current pressed state or edge — companion treats as absolute button mask after each event)
- `wheel`: vertical scroll notches (positive = up)
- `hwheel`: horizontal scroll notches

Button click pattern: send `buttons` with bit set, then clear on release. TapBoard sends press and release as separate frames.

### `key` (client → server)

```json
{"v":1,"type":"key","down":true,"hid":4,"mods":0}
```

- `hid`: HID usage ID from Keyboard/Keypad page (`0x07`)
- `mods`: bit0=LCtrl, bit1=LShift, bit2=LAlt, bit3=LGui, bit4=RCtrl, bit5=RShift, bit6=RAlt, bit7=RGui
- `down`: key press (`true`) or release (`false`)

### `ping` / `pong`

```json
{"v":1,"type":"ping","t":1710000000000}
```

```json
{"v":1,"type":"pong","t":1710000000000}
```

### `goodbye`

```json
{"v":1,"type":"goodbye"}
```

## Compatibility

Unknown `type` values should be ignored. Higher `v` is rejected with connection close after an optional error frame.
